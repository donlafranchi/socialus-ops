## Roles

- **Don (PM):** rules on scope and quality, does not read code, reviews Fri-Mon from DASHBOARD.md.
- **Cowork:** planning agent. Owns scenarios, decisions, tracking, chasing, sequencing.
- **Code:** build agent. Owns tickets, tests, merges, deploy health.
- **Dispatch:** intake and shift handoffs. Shifts 5am-5pm and 5pm-5am, max 3 area lanes, 2 build slots.

## How work flows

Five kinds of work: scenario, change, bug, process, chore. Scenarios run the full pipeline.

1. Intake: Dispatch or Don states the want.
2. Concept and research: 2-3 precedents, marked `Path: well-worn` or `new territory`.
3. Decision: logged in DECISIONS.md using the decision rule (2026-10-04).
4. Scenario: 40 lines or fewer, with a value test.
5. Tickets: one issue per testable slice.
6. Tests first, then build.
7. Journey check, visibility review, UX/UI review.
8. Fix loop, 2 rounds max.
9. Merge, then deploy-health check.
10. Live smoke.
11. PM review from DASHBOARD.md.

Pipeline detail: `process/PIPELINE.md`. Failures that shaped it: `process/LESSONS.md`.

## How we plan

- Scenarios live in `socialus-plan/planning/scenario-F###.md`.
- Shaping a new feature: the feature intake council (`planning/council/feature-intake.md`, template alongside). Nine roles imagine the best build, output is a Feature Brief with three sizes.
- Beta scoping: the existing council (9 roles, Opus chair, Haiku members) triages must-have vs later.
- Product-wide limits: six absolutes, performance budgets, accepted-risk register.

## How we build

- Code works from issues in `socialus-web`, tests first, via the `ticket`, `build`, `diagnose`, `respond` skills.
- 20 CI workflows gate merges and report health.
- Method changes go on a branch named `process-YYYY-MM-DD-slug`, commit `docs: what`, add a LESSONS line, open a PR, merge when lint is green.

## Systems in place

- **Decision rule:** how a call gets made and recorded.
- **Absolutes:** six non-negotiables, checked by `never.py`.
- **Living-doc markers:** open-question, guards, binds, platform, replaces, evidence, gates. Checked by `markers.py`, coverage via `markers.py coverage`.
- **Accepted-risk register:** JSON files, lint fails when one is overdue, `risks-due.sh` lists them.
- **Performance budgets.**
- **Status generation:** `state.sh`, `status.sh`, `status.yml`.
- **Lint:** `scripts/lint.sh` proves each checker against bad fixtures. Root .md allowlist is fixed.
- **Advisor diff:** `advisor-diff.sh`.
