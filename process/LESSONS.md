# Lessons — why this repo is the shape it is

Read before proposing any change to structure or process. Each lesson names the evidence. If a proposed change contradicts one, the proposal must say why the lesson no longer holds.

## What we learned, May–September 2026

1. **Docs checked against docs fail; docs checked against code hold.** Every gate compared a document to the one above it. Not one asked "is this still true." Explore had two tickets built after it was retired. — *retro 2026-09-03*
2. **A catalogue goes stale faster than what it catalogues.** REGISTRY, MAP, TRACE, STAGE-LEDGER, JOURNAL all retired within four months, each replaced by a smaller one. — *CLAUDE.md 2026-09-07*
3. **Absolutes multiply on their own.** 1,650 must/never/mandatory words in live docs by September; 15 numbered mandatory rules in the router; three gates to ratify the absolutes. Each one was reasonable alone. Agents obeyed the wording, not the intent. — *count 2026-09-09*
4. **"Mandatory" in one file and "optional" in the file that fires it means optional.** Review was mandatory in CLAUDE.md and optional in `review/workflow.md`. F044 and F045 shipped unreviewed. — *retro §2b*
5. **A gate judged by the party it constrains is not a gate.** M3 accessibility review was a build-time self-declaration. It was N/A'd. — *retro §2b*
6. **The reorg is the churn.** Six reorganisations May–September. Each left citations to the previous layout, which is what "stale vs current" confusion actually was. — *`_attic/2026-05-*`, `archive/2026-09-*`*
7. **Half-implemented documents confuse everyone.** A spec that describes the whole system with some of it built reads as truth to an agent. Split into as-built (matches code) and intent (a scenario with a status).
8. **Lane-by-directory needs a human to move files.** Four kanban dirs meant Don moved files on a Mac he wasn't at. State in a frontmatter field can be set from anywhere.
9. **Two agents in one working tree collide.** `index.lock` wedges, `clearlock`, commit lines handed to Don. Root cause was `web/` nested in the planning checkout, not git. Separate repos, separate clones.
10. **Nothing put work in front of Don.** Seventeen commits between pushes; five days of UI landed wrong at once. Push after every merge; a preview link beats an audit.
11. **What agents need is grep-able; what Don needs is one screen.** STATUS.md worked from day one because it is overwritten and short. Everything that appended, grew.
12. **Retired work is prior art, not a mistake.** The vendor model's analytics answered a question that came back in September. Git keeps it; the tree doesn't have to. — *writing-docs 2026-09-08*
13. **A pattern done by hand once is a pattern done differently next time.** The 2026-09-09 session classified work against PIPELINE.md, split an oversized scenario, folded reviews into the scenario's own frontmatter, trimmed `product/` to why-only, and regenerated README.md — all improvised, none written into a skill. The next session had no way to repeat any of it. — *skills sweep 2026-09-09*
14. **The principle arrived before the structure.** "Code is truth, three durable documents, everything else is a liability" was written 2026-09-07. This revamp is that principle applied, not a new idea.
15. **Skills that live nowhere load nowhere.** The six skills written 2026-09-09 sat in `ops-pattern/skills/`, which Claude Code does not read — it reads `.claude/skills/`. Meanwhile `~/.claude/skills/` held twelve symlinks into the retired `community` checkout, so every session in both repos loaded the retired pipeline (`orient`, `scope`, `weigh`, `atomize`, `tidy`) and none of the new one. Two of those links were already broken. Skills now live in `~/Projects/skills` and are symlinked per repo by `link.sh`. — *skills audit 2026-09-09*

## Guardrails for the next change

- Name the failure, with a dated example, before proposing the fix. No fixes for imagined failures.
- Small process fixes any time, with a named failure. Reorganising the tree is rare: one session, git tag first.
- Prefer deleting a doc to adding a rule. Prefer a status field to a directory. Prefer a check against code to a check against a doc.
- New absolute → a dated failure a guideline did not prevent, filed under one of the four harms in `process/ABSOLUTES.md`.
- If Don had to do something at the Mac, that's a bug in the process.
- Every change lands here first as a lesson, then in the structure.
- A standard exists when lint or CI checks it, not before.

16. **One kind of work is not enough.** Bugs, UX changes and process fixes were forced through the scenario pipeline or fell outside it. — *2026-09-10*
17. **A rule with no hook is a wish.** Every guideline names the skill, lint, or Action that fires it. — *2026-09-10*
18. **The worktree rule was scoped to branches, so sessions never got one.** `skills/build/workflow.md` has said "worktree per branch" from the start, and sessions still opened at the repo root — the one-session-per-cwd guard wedged repeatedly, and read-only sessions, which have no branch, were never covered at all. A rule scoped to the wrong noun does not fire. — *2026-09-09*
19. **`git status` is a write.** It refreshes the index, so it takes `.git/index.lock`; a sandboxed session that cannot unlink afterwards leaves a stale lock for the next one. Read as flaky git for months. `--no-optional-locks` skips the write. — *2026-09-09*
20. **An absolute violated the first time it was tested should have been a boundary.** "Code never writes to this repo" broke in the session it was first exercised: a security ruling had to land in `DECISIONS.md` and only Code had read the evidence. Replaced with a precise permission — open a PR, nothing more — rather than a broad ban nobody keeps. — *2026-09-09*
21. **"Tests pass" meant "an agent ran them on a laptop."** `issue-lint.yml` is the only workflow in `socialus-web`, so nothing independently checks a PR. The security PR that day ran the suite locally, could not apply its migration at all (Docker broken on the machine), and had no structural way to say so — draft-PR-when-unverified was invented on the spot. Verification is now a stated field, not a tone of voice. — *2026-09-09*
22. **A finding ruled acceptable is re-argued until something machine-readable holds the ruling.** The four `member_public_*` definer views and `spatial_ref_sys` were triaged from scratch against migration comments that already explained them. `accepted-risks/` + `scripts/advisor-diff.sh` make the next advisor run a diff, not a re-litigation. — *2026-09-09*
23. **Lesson 2 was written down as "no registers" and it was aimed at the wrong thing.** What rotted in REGISTRY, MAP, TRACE, STAGE-LEDGER and JOURNAL was that people read them to find out what was true, and they were wrong by the time anyone did. A file only a script compares has no such failure mode — nothing believes it, and drift is diff noise on the next run. The rule now tests who reads it to be right, not what format it is in. Stated as a ban on formats, it made every machine-readable artefact an argument. — *2026-09-09, Don*

24. **A control sized to today's vocabulary breaks when the vocabulary grows.** The browse pill row fit seven Item kinds and does not fit twelve Page categories — the words are longer and there are more of them, and a phone-width row has no give. Nothing flagged it, because the row was correct when it was built and the vocabulary changed somewhere else entirely. **The general form: any control that renders one element per term in a list is coupled to that list's length and its longest word.** When the list is a product vocabulary — categories, kinds, tags, filters — it will grow, so the control needs a shape that survives growth or a note saying what it costs to change. — *2026-09-12, Don*
25. **A standing fact about reaching Don was written into a scenario, which is deleted the moment it ships, and phrased as an absolute nobody tested against the four-harms test.** "No email, ever" landed in F078 and `DECISIONS.md` instead of `CLAUDE.md` § How to talk to Don — the durable home for exactly this kind of fact — and no dated harm was named to justify treating it as a sixth absolute rather than a guideline. Corrected same day. — *2026-09-14, Don*
26. **A naming ruling was recorded wider than Don made it, twice in four days.** "The other side is patron" was written up as a ratified *user-facing* pair, overruling `role-language.md` wholesale and retiring four of its rules; his clarification — *"shorthand for you and me when discussing the two sides broadly"* — showed only the internal half had been overruled. Lesson 25 is the same shape (a standing fact written as an absolute nobody tested). **The pattern: a short ruling gets expanded to the widest reading that makes the doc edit clean, and the expansion is invisible because it reads as a decision rather than an inference.** Two fixes, both applied: an inferred scope is labelled as a reading in the decision line, and the naming rule becomes a lint check instead of prose. — *2026-09-14*

27. **Lesson 15 fixed where skills live and not whether anything invokes them.** A `status` skill was written on 2026-09-16 to regenerate `STATUS.md`. It was complete, it was correct, and it was never symlinked into any `.claude/skills/` — so it never ran once. `STATUS.md` sat three days stale naming #12 as the launch blocker when the launch blocker was #135, and `CLAUDE.md` and the `sync` skill both told readers to call a skill that could not fire. `scripts/view.sh`, which generates `README.md`, had the same problem for a different reason: it was installed nowhere because it is not a skill at all, and nothing invoked it either. **The general form: a generator whose trigger is a person remembering has no trigger.** A document that must stay current gets a workflow, not an instruction. Fixed by `.github/workflows/status.yml`, which runs on push, on a schedule and on a button Don can press from a phone. — *2026-09-19*

28. **A test that greps a script's source cannot see whether the script works.** The production-apply preflight (`socialus-web scripts/migrations-pending.sh`) could not parse the migration history on any CI run — `supabase migration list` renders markdown when stdout is not a TTY, so every cell arrives backtick-wrapped, and the parser required bare digits. It failed closed and refused to proceed, correctly, *every time*; the first migration it ever guarded is the one it blocked. Above it sat a green test file asserting that the script's text contained "exit 3", `refs/remotes/origin` and the phrase about naming the other branch. Every assertion was true of a script that matched nothing. **The general form: a test that asserts on the text of an artefact tests that someone wrote the words, not that the thing does the job** — it is lesson 1 ("docs checked against docs fail; docs checked against code hold") one level down, where the document being checked against itself is source code. The tell is a test that never executes its subject. A guard gets a test that *runs* it against captured real-world input; a guard that has never once succeeded is indistinguishable from one that has never run. — *2026-09-19*

29. **Three planning documents all said the browse work was nearly done, and the claim was true of the database and false of the product.** `browse_feed` merged 2026-09-19 — one function, every lens axis a parameter, fully tested. `ROADMAP.md` then said it *"shipped and needs one change, a de-duplication rule"*; F091 said *"the theme is a set of queries, and the queries exist"*; F074, written the next morning, said it *"needs a de-duplication rule and nothing else."* **Nothing called it.** Only its own test file imported `getBrowseFeed`; Explore still read the old Item-grain view client-side, so no `page_posts` row could reach a reader however correct the function was. Three scenarios sat on top of that gap, and it would have surfaced in the last week before launch, as a surprise, with the theme it feeds already announced. **The general form: substrate with no caller is not a feature, and a scenario that says "the query exists" is describing substrate.** The tell is a merged artefact whose only importer is its own test — which is lesson 28's tell (*a guard that has never once succeeded is indistinguishable from one that has never run*) arriving from the other direction: there, a test that never executed its subject; here, a subject nothing but the test ever executes. **The fix is a question, asked of any claim that something shipped: what calls it?** — *2026-09-20*

30. **Three inert guards in two days is a category, so it stopped being a lesson.** Lesson 28 named one instance and lesson 29 named another; a third arrived anyway and took production down. **The general form is now an absolute — `[guard-proves-itself]` in `process/ABSOLUTES.md`: a check may not be relied on until it has been observed rejecting input that should be rejected, and an inert guard counts as absent rather than weak.** **The lesson about the lessons:** 28 and 29 were both correct, both written down, and neither had a hook — which is lesson 17 arriving a third time from a new direction. **Describing a pattern accurately does not stop it.** What stops it is a failing fixture in the same job, which is what the absolute requires. — *2026-09-21*

31. **An open question lived in three places, and a list of what Don owed was carried forward unread.** On 2026-09-27 F080's detection question stood in `DECISIONS.md` § Open, in F080 § Why and in #221 — three copies, written the same day. F071 had routed its questions to `DECISIONS.md` because the scenario format had nowhere to put them. `STATUS.md`'s Waiting-on-Don list was copied from each run to the next and labelled *not re-verified*, for eight days. **The general form: a question written away from where it is answered is a register, and a register is lesson 2.** Fixed by an inline marker with an owner and a date, a generated index, and a lint that proves itself on a bad fixture — `process/PIPELINE.md` § Open questions. **The lint's first observed run found it was inert** (`pipefail` swallowed the exit code), which is `[guard-proves-itself]` earning its keep on day one. — *2026-09-27, Don*

32. **Every question Don asked that spanned the project was answered by someone reading, and nothing he was told stayed true.** On 2026-09-27: four scenarios claimed `building` and nothing checked it — one had no commit, file or branch naming it; accepted risks carried revisit dates (2026-10-16, 2026-11-30) that nothing enforced; F093 required every criterion be discharged by a check seen failing, and nothing could say which check discharged which. **The general form: a fact kept anywhere but where it is true needs someone to remember it, and a cross-cutting answer assembled by reading is stale the moment it is read** — lesson 2, and 23, and 27, from the reader's side. Fixed as a pattern, not a document: inline markers, generated views, a lint on each — `process/LIVING-DOCS.md`. — *2026-09-27, Don*

33. **Superseded rulings were kept beside their replacements, so every reader re-derived precedence — and when they could not, they asked Don.** On 2026-09-27 five were found in prose only, one arguing at length that it was not a reversal; #220 asked Don to confirm a newer ruling over an older one. The first fix annotated both ends and kept the old text; Don's correction the same day: **a superseded entry kept inline is a second copy of what git already holds, and a file that only grows.** Now deleted, with one `[replaces …]` line on the new entry — `[newer-decision-wins]`, and rule 4 of `process/LIVING-DOCS.md`. — *2026-09-27, Don*

34. **Three generated views reported what they were not checking.** On 2026-09-29: the coverage map read F093 criteria as covered when their checks covered half of each; 21 of 22 approved and building scenarios had no marked check, and the map said nothing about them; the gating check read scenarios only, so the 2026-09-21 identity-leak ruling bound code for eight days with no Issue. **The general form: a view that is silent about what it cannot see reads as a view that saw nothing wrong** — the inert guard (`[guard-proves-itself]`) one level up. Fixed with a partial state, an unverified count in `STATUS.md`, and a lint on code-binding rulings with no Issue — `process/LIVING-DOCS.md`. — *2026-09-29*

35. **Rule violations reached the PM as if they were judgement calls, because no role owned the first look.** On 2026-10-04 CI captured every route as every persona and nobody reviewed the pictures (`socialus-design/research/PATTERNS.md` § E2). Don ruled that a separate reviewer agent runs a first pass before any `needs-don` PR: persona screenshots at phone and laptop width, copy and behaviour against the rulings, fixes made and listed in the PR body. `PIPELINE.md` § A reviewer's first pass.

36. **Builds, tests and browsers competed for one machine, with no limit on how many ran at once.** Don set build rules on 2026-10-04: at most two changes building or testing, Playwright at two workers, one dev server per change, browsers closed after each run, persona reviews as a serial queue, browser and build work serialized, and any rule that would slow a deadline flagged before it is broken. The specific incident was not recorded here. `PIPELINE.md` § Build rules.

37. **UI was invented case by case, and every visible change went to the PM.** On 2026-10-04 Don ruled that every UI feature starts from 2–3 named best-in-class precedents, recorded in the Issue and PR and checked by the reviewer, and that precedent-following, reviewed UI merges without him; he sees judgement calls only (tone, conflicting precedents, rulings). The specific incident was not recorded here. `PIPELINE.md` § Precedent first.

38. **Agents waited on the PM for decisions an established platform had already made.** On 2026-10-04 Don gave a decision rule for every agent: look at 2–3 precedents first, choose the simplest that fits the rulings, build a well-worn path yourself (`Path: well-worn`), and bring only new territory to the PM as A/B/C (`Path: new territory`). It replaces the narrower UI precedent rule of the same morning (lesson 37). `PIPELINE.md` § Decision rule.

39. **The method and the product shared one repo, so the method could not be reused and every agent read both.** On 2026-10-04 Don asked for the split: `ops-pattern` keeps the method (absolutes, pipeline, living docs, lessons, scripts, templates); SocialUs planning moved to `socialus-plan` with its history. Scripts are vendored, so a method change is made here first and then copied.

40. **Authored docs went stale with nothing to show it.** On 2026-10-05 the member journey and the use cases still described maker and provider profiles and b1/b2 bundles, days after "no public member profile" (2026-10-01) and the beta trim; their last commit was a day old, from an unrelated move, so nothing looked old. Proposed: an authored doc carries `reviewed:` in its frontmatter, and STATUS lists docs by review age (GOV.UK tech docs' `last_reviewed_on` is the precedent). `scripts/status.sh` § Docs by review age.

41. **The first pass was skipped silently, and nothing said so.** `socialus-web` #380, the operator's review page, merged on 2026-10-05 without a reviewer's first pass, because Docker was down and the pass needs the local stack. The PR said so in passing, but nothing stopped the merge or kept a record of it, and the pass checked precedents and rulings with no explicit look at accessibility, states or thumb reach. Two fixes, the same day, on the PM's question of whether reviews check the important UX: the first pass carries a UX checklist the reviewer ticks in the PR body (`PIPELINE.md` § A reviewer's first pass), and a UI PR without it fails a check unless it is labelled `review-skipped` with a reason.

42. **Fields were built because they were possible, not because they belonged here.** On 2026-10-05 business hours were hidden after they cluttered the Page; they already lived on the business's own site and Google, went stale unless the owner kept them up, and brought nobody together. Don ruled a value test: six questions every new scenario answers in `## Why` before acceptance criteria are written, checked by `scripts/lint.sh` from F103 on. `PIPELINE.md` § Rules of the road.

43. **Work reached the PM as lists, file edits and approval cards he could not see.** On 2026-10-05 he was sent everything needed before beta at once, was asked to edit files, and was asked to rule on decisions that were not a current concern; PRs opened through the GitHub connector sat behind an approval card he never sees, and mechanical work (merges, env vars, reruns) waited on him. He ruled the PM queue: one item at a time, agents edit, agents do the mechanical work, no speculative rulings. `PIPELINE.md` § Working with the PM.

44. **Work landed in the wrong repo, and personal names were written into repos.** On 2026-10-05 the PM restated the boundaries: plan holds features, ops the method, web the code, and a private legal repo holds legal, entity and anonymity work, which never goes in plan or ops; no personal names appear in a public repo (currently `socialus-web`); plan and ops are scrubbed when they go public. `PIPELINE.md` § Working with the PM.

45. **Worktrees were never removed, and they filled the disk.** On 2026-10-05 136 stale worktrees used 78GB and filled the build machine's disk. The PM ruled that the agent that merges a branch removes its worktree that day, when the tree is clean and nothing is unpushed, then prunes. `PIPELINE.md` § Build rules.

46. **One worktree per branch, each with its own `node_modules` and `.next`, was the disk bloat; the rest is background.** Read-only measurement, 2026-10-05, `du` on the Mac. `~/Projects/worktrees` held 139 worktrees at 73.8GB, 0.53GB each: `node_modules` 65.9GB in 100 trees (about 0.66GB a tree, a fresh install each) and `.next` 7.1GB in 46 trees (up to 1GB in one). They were created at about 5 a day over 26 days and 15 to 24 on the busiest days (2026-10-01, 10-04, 10-05), so roughly 10GB a day of heavy building and nothing ever removed them (lesson 45). Next: Docker Desktop's disk image held 48.5GB of a 500GB sparse file (the daemon was stopped, so its image, volume and build-cache split is unmeasured); the npm cache 6.9GB, plus 1.2GB of npx; the Claude desktop app 12.1GB, of which 9.9GB is its VM bundle, a fixed size and not agent-made, and 0.5GB local agent sessions; Playwright browsers 1.6GB in `~/Library/Caches/ms-playwright` (one copy, shared, fine); Xcode and simulators 2.2GB; a retired duplicate checkout, `~/Projects/community`, 2.4GB. Growth is set by worktrees per day times 0.5GB; the others are flat or slow. The rules that stop it: clone `node_modules` rather than reinstalling, delete `.next` after a run, cap live worktrees at 10, remove one the day its branch merges, no second clone, and a weekly prune. `PIPELINE.md` § Build rules.
